# PBNS COSE_Encrypt v1 interoperability vectors

These immutable test vectors contain no deployment secrets. Both encrypt the plaintext `pbns interop payload` for recipient `kid` `pbns-recipient-v1` with external AAD `PBNS-ENCRYPT-INTEROP-v1` using P-256 ECDH-ES+A128KW (`-29`) and A128GCM (`1`). Both messages carry COSE_Encrypt tag 96.

- `tcose-to-cosec.cbor` was generated by `pbns_encrypt_for_recipient` through pinned `t_cose` and is decrypted by the COSE-C bridge.
- `cosec-to-tcose.cbor` was generated by `cosebridge.Encrypt` through pinned COSE-C and is decrypted by `pbns_decrypt_for_recipient` through `t_cose`.
- `uefi-to-cosec.cbor` was generated by the OVMF `PbnsCoseProbe.efi` t_cose/Mbed TLS adapter and is independently decrypted by the gateway COSE-C bridge.

ECDH ephemeral keys, CEKs, and IVs are random, so regeneration produces different valid bytes. The checked files are fixed verification vectors:

```text
b37b3d7543e53db14459d6fa7eed966fd8e74e3ea4b42867be5e6fc495b9c5c4  tcose-to-cosec.cbor
9c72b764571c1c843c3d271b3db01bc4d206e4f112468c36eea328731c759014  uefi-to-cosec.cbor
```

COSE-C, `t_cose`, and cn-cbor are built from untouched pinned submodules in ignored generated trees. The dependency checker permits only the reviewed compatibility patches under `patches/COSE-C/`, `patches/t_cose/`, and `patches/cn-cbor/`; no modified third-party source is committed.
